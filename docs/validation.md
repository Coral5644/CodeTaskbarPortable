- 现场三个网易 Minecraft 3.9.0.401155 进程分别具有 `InvManager_main`、`InvManager-lane-a`、`InvManager-lane-b` 的 config 路径；其中一项经中间脚本启动，说明不能仅用共同 Code 父进程或启动顺序推断工作区。
- 对仍在运行的主开发区和 lane-a 游戏，接管后的任务栏身份按 HWND/PID 独立，自定义标签分别包含对应配置目录名与 PID；Explorer 的 DisplayName getter 实际成功返回过各自标签。原生窗口标题保持原样。检查过程中用户关闭的游戏不计入后续仍存活窗口断言。
- 14 项识别测试通过：斜杠与反斜杠、主开发区和并行开发区、中文与空格、参数大小写、缺少参数与不正确路径、相同开发区的 PID 区分、本机真实 WMI 命令行读取及不存在 PID 的回退。
- VS 2022 `/W4 /WX` 构建通过，PowerShell 7 与 Windows PowerShell 5.1 smoke 均通过。
- 只读运行时工具核对窗口实际 AppUserModelID、从游戏真实命令行生成的标签与已发生的标签返回。分别在正常退出和强制结束助手控制进程后，核对仍存在的目标窗口已恢复原始任务栏身份；未结束游戏进程。
- 一次约 32 秒的已启动样本中，控制进程累计 CPU 增量低于该次测量精度，工作集约 18 MiB、私有内存约 2.6 MiB。这是短时本机样本，不代表所有工作负载或整个 Explorer 的总开销。

游戏命令行通过系统 [Win32_Process 的 CommandLine 属性](https://learn.microsoft.com/en-us/windows/win32/cimwin32prov/win32-process) 读取；只在首次接管窗口时查询，不引入周期扫描。无可靠 config 参数时保留 PID 标签并标明未识别，不宣称已建立 VS Code 工作区关联。配置目录名可能与 VS Code 文件夹显示名不同，例如 `InvManager_main` 对应现场的 `InvManager` 主开发区。

## 自动检查

构建后执行 `tests/smoke.ps1`。测试会短暂启用当前构建、读取状态，再退出恢复；不要与其他已运行的本工具实例同时进行。

检查内容包括简体中文 PE 版本信息、嵌入图标、无主窗口的后台运行、单实例、中文状态、正常退出，以及缺少 DLL 时不弹框但保留失败状态托盘入口。结果写入忽略提交的 `build/smoke-result.json`。

## 本机界面验证

1. 保持 Windows 全局设置为“始终合并任务栏按钮并隐藏标签”。
2. 打开两个 VS Code 测试窗口，检查是否分别显示原生按钮和各自标题。
3. 启动助手后再新建第三个窗口，检查能否自动处理。
4. 修改测试窗口标题，检查标签是否跟随更新。
5. 检查其他应用的两个窗口仍然合并且不显示文字。
6. 从托盘查看状态、日志，并选择退出恢复。
7. 重新启动后，只结束助手控制进程，检查 DLL 能否在进程退出后恢复。

不要为测试而结束用户的其他进程或主动重启 Explorer。多屏和系统更新后的兼容性需单独验证，不能从编译成功推断。

## 版本适配

源代码中的模块 RVA 仅对 `supported-windows.json` 指定的组件有效。适配新版本时，应重新核对符号、接口布局和函数表入口，更新文件哈希及 PDB 标识，然后在对应系统上验证。不能通过删除校验来声称兼容。
